# RAG 评测体系报告

**日期**：2026-10-23 ｜ **系统**：wgh-rag-system ｜ **评测脚本**：[eval_rag.py](eval_rag.py)
**评测集**：qa-1000.pdf（1000 条问答，8 领域，已入库，FAQ 策略切分 1001 chunks）

---

## 一、评测方法与结果

### 1. 检索指标（40 条抽样查询，topK=5）

| 指标 | 定义 | 结果 |
|------|------|------|
| Recall@5（查询级） | top5 中至少含 1 个相关 chunk 的查询占比 | **1.000** |
| MRR@5 | 第一个相关 chunk 排名倒数的均值 | **1.000** |
| NDCG@5 | 二元增益按位置折损 / 理想折损 | **1.000** |

- 相关性判定：chunk 文本包含查询问题的核心子串（去标点空格）
- 抽样方式：1000 条每隔 25 条取 1 条，均匀覆盖 8 章
- 耗时：40 查询共 8s（单次检索约 200ms，含 embedding API 调用）

### 2. 双 Judge Faithfulness（10 条样本）

| Judge | 平均 Faithfulness | 与另一 judge 差值 |
|-------|------------------|-------------------|
| DeepSeek（deepseek-chat） | **1.000** | 全部 0.00 |
| Qwen（qwen-plus） | **1.000** | 全部 0.00 |

- 生成：检索 top3 上下文 → DeepSeek 按 RAG prompt 生成回答
- 评判：judge 将回答拆为原子声明，逐条判断是否被上下文支持，输出 `supported/total`
- **双 judge 一致性：100%**（|diff| < 0.15 阈值）

### 3. 解析器对比

| 解析器 | 行首「问N：」识别数 | 结论 |
|--------|---------------------|------|
| PDFBox（线上） | 1001 单元（1000 问答 + 标题头） | 文本型 PDF 完整识别 |
| pdfplumber | 1000/1000 行 | 与 PDFBox 等效 |

**结论**：对纯文本型 PDF，PDFBox 足够，无需替换；pdfplumber 的价值在表格抽取（`extract_tables()`），Apache Tika 的价值在多格式统一（word/ppt/html）与元数据——当前文档类型下暂无需替换，列入触发式演进（见三.3）。

## 二、批判性解读（重要）

满分结果**不能**直接证明系统对真实用户查询的表现，原因：

1. **自检索偏差（self-retrieval）**：ground truth 查询文本几乎逐字存在于 chunk 中（FAQ chunk 以「问N：问题原文」开头），向量检索命中近似精确匹配，满分是必然。真实用户会以同义改写、口语化、不完整句提问。
2. **生成-评判同模型偏好**：Faithfulness 的回答由 DeepSeek 生成，虽然双 judge（含 Qwen）均满分、一致性 100%，但评测集问答对本身结构规整、上下文完整包含答案，属于"简单查询"场景——印证了 RAGAS 类指标"简单查询有效、复杂领域需校准"的已知局限。
3. **无负样本**：未测试"知识库不存在答案"时系统是否正确拒答（防幻觉的关键指标）。

**当前满分的正确解读**：链路无功能缺陷（分割→向量→检索→生成全链路通畅），FAQ 分块策略对问答文档有效。

## 三、后续评测演进方向

1. **区分度评测集**：对 1000 条种子问题做同义改写（让 LLM 生成"口语化提问"版本），用改写后查询重跑检索指标——预期 Recall 下降，此时数值才有区分度
2. **负样本测试**：构造 20 条知识库外问题，检验系统是否拒答而非编造（Faithfulness 的另一面）
3. **触发式解析器升级**：当出现表格密集 PDF（chunk 切断表格行）或扫描件（PDFBox 提取为空）时，再引入 pdfplumber 表格管线或 Tika
4. **常态化评测**：eval_rag.py 可在每次调整分割策略/embedding 模型/检索参数后重跑，指标回归对比
