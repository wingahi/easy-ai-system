## 1. 调度中心

### 1.1 为什么改

原调度只有全局并发上限：单租户可占满后台队列；进程内并发计数在多副本下不成立；
失败作业缺少管理端入口，排障要直连数据库；长任务仍绑定请求线程与 `SseEmitter`，
断线即失败、跨副本无法续看。

### 1.2 租户调度策略与准入（`3806a8a`）

- 新增 `wgh_tenant_schedule_policy`：按 `(tenant_id, lane)` 唯一，`lane` 取
  `INTERACTIVE / BACKGROUND / MAINTENANCE`；字段含 `max_concurrent`、`max_queue`、`weight`、
  `priority_boost`、`reject_policy`、`queue_timeout_seconds`、`daily_job_limit`、`rate_per_minute`、
  `time_window_json`、`version`（乐观锁）。
- 准入顺序：先判全局上限，再判租户约束；交互车道并发满按 `REJECT`，后台车道按 `QUEUE` 排队并受
  `max_queue` 约束；维护车道不受租户策略限制。拒绝统一返回 `SCHEDULER_REJECTED`。
- `PolicyCache`：本地缓存 `(tenant_id, lane)` 策略，默认 30s 刷新，管理端写入后主动 reload；
  策略表缺失或查询失败时按代码/配置默认值降级（交互 2 并发 / 20 排队，后台 2 并发 / 200 排队）。
- 空租户统一落到 `wgh.scheduler.anonymous-tenant-id`（默认 `default`），与
  `ExecutionRequest.DEFAULT_TENANT` 一致。
- 指标：`wgh.scheduler.rejected`、`wgh.scheduler.wait.seconds`、`wgh.scheduler.job.duration`、
  `wgh.scheduler.policy.load.failures`。
- **已建模未启用**：`daily_job_limit` / `rate_per_minute` / `time_window_json` 已落表并透出，
  准入暂只执行并发、排队与拒绝方式。

### 1.3 集群运行槽与漂移（`3806a8a`）

- 新增 `wgh_tenant_runtime_slot`，主键 `(tenant_id, lane)`，记录 `running` 数量；
  后台作业执行前占槽、结束释放。
- 周期对账（默认 1m）用作业表「实际在跑数」校正槽位，偏差计入 `wgh.scheduler.slot.drift` 指标，
  用于收口进程异常退出造成的槽位泄漏。
- 槽位表不可用时**失败开放**并只告警，不阻断作业领取；交互车道仍以作业/运行登记计数为准，
  不强制走租户槽位。

### 1.4 管理端：策略、失败重试与强制回收（`ae847df`）

新增/扩展 `/api/admin/scheduler` 接口：

| 方法 | 路径 | 作用 |
| --- | --- | --- |
| GET | `/overview`、`/instances`、`/reconcile`、`/runtime` | 运行时与实例、对账快照 |
| GET | `/jobs`、`/jobs/failures`、`/jobs/{executionId}` | 作业列表、失败队列、单作业详情 |
| POST | `/jobs/{executionId}/cancel`、`/retry`、`/reclaim` | 取消、重试、强制回收 |
| GET | `/policies`；GET/PUT `/policies/{tenantId}` | 策略列表、单租户查询与更新（更新必须带 `version`） |
| POST | `/policies/{tenantId}/dry-run` | 准入试算，只模拟不提交作业 |

- 强制回收把作业置回 `PENDING` 并记录原因与操作人，写 `@Audit`；
  重试与回收均校验当前状态，避免并发下重复操作。
- `SchedulerCenter.vue` 页面新增四个页签：作业执行 / 租户策略 / 失败与死信 / 实例与对账；
  失败列表走 `GET /jobs/failures`，策略编辑带乐观锁版本。
- 调度读/写共用 `PERM_AUDIT_VIEW`，本轮未拆 `scheduler:view` / `scheduler:manage`。

### 1.5 执行事件表与断线重放（`7393799`）

- 新增 `wgh_execution_event`：`execution_id + seq` 唯一，`seq` 从 1 单调递增；
  只增不改，按 `wgh.scheduler.event-table-retention`（默认 7d）由调度层低频清理。
- 事件总线以订阅者方式把事件同步落库；**写入失败只告警，不影响执行**。
- 新增 `GET /api/executions/{executionId}`（执行状态）与
  `GET /api/executions/{executionId}/events`（SSE，支持 `Last-Event-ID` 从任意副本补齐）。
- 多 Agent 与聊天工作流抽出传输无关的 `AgentEventStream`（`SseAgentEventStream` /
  `JobAgentEventStream`），不再依赖 HTTP/`SseEmitter` 对象。
- 边界：跨副本只支持**重放**，跨副本**实时 tail** 仍依赖执行实例内存总线。

### 1.6 后台作业化

| 执行体 | 作业类型 | 说明 |
| --- | --- | --- |
| 评测 | `EVAL_RUN` | 接口返回 202 + `executionId`，`GET /api/kb/{kbId}/eval-datasets/{datasetId}/evaluate/runs/{executionId}` 轮询；未启用调度时保留同步返回 |
| 单 Agent 计划 | `AGENT_PLAN` | HITL 确认续跑后台化（业务键 `agent-hitl:{stepId}`）；首轮 ReAct 计划仍在聊天流式链路 |
| 多 Agent | `AGENT_MULTI_RUN` / `AGENT_MULTI_HITL` | 后台执行 + attach 到 SSE；HITL 续跑走作业 |
| 聊天工作流 | `WF_CHAT_RUN` / `WF_CHAT_HITL` | `runForChatBlocking` / `resumeForChatBlocking`；确认与扣费先独立事务提交，再同步续跑 |
| 语义缓存清理 | `KB_SEMCACHE_CLEANUP` | 从「写入节奏触发」改为周期作业 |
| 向量事实层回填 | `KB_VECTOR_BACKFILL` | 类型已登记，实现随检索改造（见 §3.2） |

- HITL 确认与续跑收敛到后台作业，确认闸门（条件 UPDATE）保证只扣费一次。
- 前端：评测与 HITL 改为轮询到终态；多 Agent、聊天工作流仍以事件流呈现进度。

### 1.7 语义缓存周期清理（`7393799`）

`wgh.rag.cache.cleanup-interval-minutes`（默认 30，最小 5）控制 `KB_SEMCACHE_CLEANUP` 的提交间隔；
查询侧仍按 TTL 过滤，清理只影响存储占用，不改变命中语义。

### 1.8 行为变化

- 单租户占满队列的情况被 `(tenant, lane)` 策略约束；后台作业多了排队与拒绝原因。
- 失败作业可在管理端重试或强制回收，不必直连数据库。
- 长任务断线后可按 `Last-Event-ID` 补齐事件；评测、Agent、多 Agent、聊天工作流不再强绑请求线程。
- 运行时端到端验证已在 dev 通过（调度页签、SSE attach / 重放、后台作业、HITL 扣费与结算），
  期间修复：attach 兜底轮询、`fromSeq=0` 全量重放、作业线程恢复属主角色、payload 过滤 `null`、
  续跑事务边界。

## 2. 多租户隔离

### 2.1 越权入口收口（阶段 0，`530f4d6`）

- 知识库子资源统一做父 KB 可读/可写校验；评测数据集改为「可见且可写」。
- 开放 API 绑定 Key 的 owner 并继承其可见性；`/api/open/**` 与 OpenAI 兼容入口按 Key owner 收口。
- 多 Agent 运行态补归属校验（stream / state / hitl / cancel / steps）。
- 分享链接与 API Key 列表按 owner 过滤。
- 风险：历史上「全局 Key」的调用方会收到 403/404，需要兼容期与公告。

### 2.2 租户模型与上下文传播（阶段 1，`530f4d6`）

- 新增 `wgh_tenant`（`code` 全局唯一，业务表 `tenant_id` 存该 code；默认租户 `default`）；
  存量用户、审计、API Key 回填到 `default`，存量部署零迁移。
- `TenantContext`（ThreadLocal + MDC）：只从可信凭证建立（本地 token / OIDC claim），
  认证后过滤器写入，请求结束 `finally` 清理。
- `AuthContextPropagation` 覆盖 `@Async`、调度作业线程、工作流线程池、Agent 超时子线程；
  作业 payload 携带 `tenantId` / `ownerUserId`，worker 执行前恢复。
- 租户管理端扩到 **9 个端点**：`GET/POST /api/admin/tenants`、`PUT /{id}`、`PATCH /{id}/status`、
  `DELETE /{id}`（逻辑下线，保留业务数据）、`GET/PUT /{id}/quota`、`GET/PUT /{id}/schedule-policy`；
  权限码拆为 `tenant:manage`（列表/创建/启停）、`tenant:update`、`tenant:disable`、`tenant:quota`、
  `tenant:schedule`。
- 写操作全部落审计（`TENANT_CREATE` / `TENANT_UPDATE` / `TENANT_STATUS_UPDATE` / `TENANT_OFFLINE` /
  `TENANT_QUOTA_UPDATE` / `TENANT_SCHEDULE_UPDATE`）；下线只改租户状态，不删业务数据。
- 新增 `wgh_tenant_quota_config`（租户级日/月请求数与 token 上限，平台配置表，不做 RLS）；
  管理端用户列表展示所属租户，创建/编辑支持分配租户（`tenant:manage`，禁止改自己）。
- 前端新增 `/admin/tenants` 页面（列表、创建、编辑、启停/下线、配额、调度策略），
  用户管理页增加租户列与分配入口。
- `wgh.tenant.enforcement` 默认 `false`：未知租户回落 `default`；置 `true` 后未知/停用租户的令牌与
  API Key 一律拒绝（多租户正式上线前置条件）。
- 停用租户的令牌即使非严格模式也不会回落默认租户。

### 2.3 MyBatis 租户插件与 34 张表（阶段 2，`530f4d6`）

- `TenantLineHandlerImpl` + `TenantTableRegistry` 白名单自动追加 `tenant_id` 条件；
  白名单 38 张 = 本批新增 34 张 + 既有 4 张（`wgh_kb_chunk`、`wgh_api_key`、`wgh_api_call_log`、`wgh_audit_log`）。
- 34 张业务表补 `tenant_id VARCHAR(64) NOT NULL DEFAULT 'default'`（知识库、对话、评测、Agent/多 Agent、
  工作流、配额等域），每条列带索引；平台共享表（用户/角色/权限/模型/价格/租户目录/调度实例）不加。
- 无租户上下文（启动、维护、匿名公开链路）与 `admin` 不追加条件；业务入口仍保留父资源校验，
  插件只做纵深防御。
- 新增表必须同时改 SQL 与 `TenantTableRegistry`，两处不一致会漏隔离。

### 2.4 存储、缓存与向量 metadata

- 存储 key：默认租户沿用 `kb/{kbId}/{uuid}/{file}`（存量零迁移）；非默认租户为 `t/{tenantId}/kb/...`。
- `UploadSession.tenant_id` 在初始化时冻结，续传/合并不再依赖线程上下文。
- 孤儿清理：只按租户前缀列举（`listByPrefix`），`KnowledgeFile` / `UploadSession` 查询显式限定
  `tenant_id`；key 无法解析租户或不在扫描前缀内一律跳过、不删除。
- SSE 重放缓冲与对话取消标记改为 `{root}:t:{tenantId}:...`（临时 key，无需迁移）。
- 用户信息缓存与 JWKS 属平台级共享，不做租户化。

### 2.5 向量与关键词 metadata

- KB chunk 与共享集合（语义缓存、Agent 记忆）写入时带 `tenantId`；事实层回填缺省时按
  `wgh_kb_chunk.tenant_id` 补齐。
- 检索编排层对非默认租户在向量、关键词两路统一下发租户断言（端口过滤字段为租户 code 字符串）；
  默认租户与无上下文链路不加条件，保证存量无 `tenantId` 的向量仍可读。

### 2.6 RLS 脚本与 dev 验收（阶段 3，`b08b304`）

- 新增 7 个脚本（`09`～`15`，见 §4.2）：`wgh_app` / `wgh_platform` / `wgh_scheduler` / `wgh_preauth`
  四角色；A 组 32 张标准表、B 组 4 张免登录/日志表、Prompt/Tool 2 张（`scope` 列）、调度 3 张的事务级策略；
  回滚脚本与只读核对脚本。
- 策略谓词统一为 `tenant_id = current_setting('app.tenant_id', true)`（`VARCHAR` 文本比较，不做 `::bigint`）；
  使用事务级 `set_config(..., true)`，不切 Hikari 全局 `auto-commit=false`；缺 GUC 时 fail-closed。
- **dev 验收结果（`wgh_rag_dev`）**：按 `09` → `10`(A) → `11`(B) → `13`(D) → `12`(Prompt/Tool) 执行并逐组验收，
  最终 41 张表 `rowsecurity=t` / `forcerowsecurity=t`、52 条策略。实测：`wgh_app` 无 GUC 时
  `wgh_knowledge_base` / `wgh_execution_job` 均 0 行，GUC=`default` 时 8 行且无其他租户行，
  GUC=`t-other` 时 0 行；越权 `UPDATE` 被 `new row violates row-level security policy` 拒绝；
  `wgh_preauth` 仅可读 `share_link` / `api_key`；`wgh_scheduler` 可读 1233 行调度作业、业务表
  `permission denied`；`wgh_platform` 可跨租户只读审计 458 行 / 调用日志 322 行、业务表无权限；
  `EXPLAIN` 显示 `Bitmap Index Scan on idx_chat_message_tenant`，谓词已下推。
- **应用侧已切换（dev，阶段 B/C 验证通过）**：`application-dev.yml` 默认
  `WGH_DB_USERNAME=wgh_app`、口令由环境变量注入；`TenantAwareDataSourceTransactionManager`
  在事务开始时对连接执行 `set_config('app.tenant_id', ?, true)`，`guc-enabled` /
  `role-switch-enabled` 默认 `true`；业务读入口补齐 `@Transactional(readOnly=true)`，
  免登录（`wgh_preauth`）与调度（`wgh_scheduler`）链路在独立短事务内 `SET LOCAL ROLE`。

## 3. 向量库与搜索引擎

### 3.1 端口契约与后端路由（`c334e0e`）

- `VectorStorePort` 扩为可替换契约：`upsert`、`insertVectors`、`scan`、`describe`、`search`、
  `deleteByEmbeddingIds` / `deleteByFileId` 等；新增 `VectorStoreBackend`、`VectorRecord`、
  `VectorMatch`、`VectorFilter`、`VectorRange`、`VectorScoreType`、`ScanPage`、`CollectionInfo`。
- `KeywordSearchPort` 补 `KeywordSearchBackend`、`KeywordFilter` / `KeywordHit`、
  `KeywordIndexMaintenance`（增删索引按后端路由）。
- `VectorStoreRouter` / `KeywordSearchRouter`：按 `wgh.vector.backend` / `wgh.search.backend` 选实现，
  业务只注入路由 Bean；默认 `pgvector` / `pgtrgm`，另提供 `memory` 实现（仅开发测试）。
- 关键词路支持 `fallback-backend` 与 `degrade-on-error`：主后端异常时降级到兜底后端并记
  `wgh.retrieval.degraded`，保证聊天主链路不中断。
- 向量与语义缓存 metadata 写入/过滤均携带 `tenantId`（见 §2.5）。

### 3.2 `wgh_kb_chunk` 事实层与回填（`c334e0e`）

- 新增事实层 `wgh_kb_chunk`：`tenant_id`、`kb_id`、`file_id`、`chunk_index`、`content`、
  `content_hash`、`metadata_json`、`embedding_id`、`dimension`、`vector_status`
  （`PENDING / SYNCED / STALE`）；唯一键 `(kb_id, file_id, chunk_index) WHERE deleted=0`。
- 定位：原文与元数据的唯一副本，向量/关键词索引均可按事实层重建。
- `KbChunkService` 提供双写（`replaceFileChunks` / `markSynced`）、文件删除清理、
  `backfill` 回填与 `reconcile`（事实层与向量表条数对账）。
- 开关 `wgh.vector.fact-layer-enabled`（默认 `false`）：关闭时不改变写入链路。
- 回填作业 `KB_VECTOR_BACKFILL` 已登记类型，按批（默认 200）回填。

### 3.3 V1：双读对比、灰度、RRF 与双路删除（`c334e0e`）

- 双读对比：`wgh.search.compare-enabled` / `compare-backend`，同一 query 两路都跑，
  **只记录 top1/集合差异，不改变返回**。
- 灰度：`wgh.search.gray-backend` + `gray-kb-ids`，按 KB 白名单走灰度后端，其余走主后端。
- 融合：`wgh.retrieval.fusion.rrf-k`（默认 60）、`vector-weight` / `keyword-weight`（默认 1.0），
  默认值与引入权重前完全一致。
- 删除：文件删除/重切时清理事实层，同时按后端 `applyAll` 清理向量与关键词索引（双路删除）。
- 语义缓存与 Agent 记忆的共享集合写入强制带 `tenantId`，非默认租户查询追加租户条件。

3. **trusted 镜像仅覆盖 dev**：生产未纳入镜像构建/发布链，扩展仍由 DBA 预建。
4. 跨副本实时 tail（订阅）未实现；事件表写放大未压测。
5. 检索质量（Recall@K / NDCG / P95）未实测；双读对比与灰度未在真实流量开启。
6. 存储孤儿清理切换租户前缀后的差异未做只读比对。
7. 多租户跨租户负向自动化用例（路线图 M1）未补；启动自检未开启 fail-fast。
8. **test / prod 存量库仍缺 `16` 内容**：`01-schema.sql` 已并入 `wgh_tenant_quota_config` 与 4 个租户权限码
   （临时库验证可幂等执行），新库无需补执；`test` / `prod` 存量库上线租户管理端前仍需执行 `16_tenant_admin.sql`。

## 6. 已知限制

1. **默认租户不做向量过滤**：默认租户与无上下文链路不加 `tenantId` 条件，
   存量无 `tenantId` 的缓存/记忆向量仍可能被读到。
2. **历史缓存与记忆向量无 `tenantId`**：改造前写入的语义缓存与 Agent 记忆向量不带租户字段，
   非默认租户过滤后可能召回不到，需按需重建。
3. **`EVAL_RUN` 之外仍有同步路径**：调度未启用时评测保留同步返回；单 Agent 首轮计划仍走聊天 SSE；
   工作流聊天沿用既有事件契约。
4. **事件表写放大**：每个事件（含高频 `DELTA`）同步落库，未做异步批量或按类型过滤。
5. **admin 即平台管理员**：未拆分 `platform_admin`，无法区分平台运维与租户业务管理员。
6. **`username` 全局唯一**：未改为 `(tenant_id, username)`，不同租户不能使用相同用户名。
7. **交互车道不强制租户槽位**：`wgh_tenant_runtime_slot` 仅后台车道强制；交互车道仍以运行登记计数为准。
8. **策略字段部分未执行**：`daily_job_limit` / `rate_per_minute` / `time_window_json` 已落表但未强制。
9. **RLS 生效依赖连接用户与事务**：必须 `wgh_app` + 事务级 GUC（禁止会话级 `SET ROLE`）；
   `prod` / `wgh_rag_test` 未切换前仍为应用层过滤。
10. **平台管理员跨租户业务读取在 RLS 下默认不可见**；`wgh_prompt_template.name` 仍全局唯一。
11. **`PUBLIC` 语义已收敛为租户内公开**；跨租户共享需改用平台标记（未实现）。
12. **跨副本仅重放**：不支持实时 tail；断线重连依赖事件表与客户端游标。
13. **平台级扫描默认串行、单轮上限 200 租户**（`wgh.platform-scan.*` 可调并发）：超出截断到下一轮，
    单租户失败只告警，不保证一轮内覆盖全部租户。
14. **trusted 镜像只改变扩展安装权限**：不会把 `extowner` 改写为超级用户；若由 `wgh_app` 安装，
    属主即 `wgh_app`（需评估 `DROP/ALTER EXTENSION` 权限面）；dev 现有扩展仍属 `postgres`。
15. **启动自检未强制**：`superuser / BYPASSRLS / INHERIT` 目前只告警，误配不会阻止启动。
16. **平台角色视图收窄**：`wgh_platform` 只读审计/调用日志，业务表不可见；跨租户业务运维需按租户切换。
17. **`wgh_tenant_quota_config` 不做 RLS**：作为平台配置表仅由管理端读写，租户侧不可见。
