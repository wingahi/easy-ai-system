## 3. 缺陷明细

### 3.1 BUG-01（高）流式对话“首次产出结算”竞态：先退款、后产出，全部对话不计费

- 关联用例：QCHG-17（失败）、QCHG-19（现象通过但原因错误）、QCHG-20/21（同路径，未单独执行）
- 实际现象：7 次对话（浏览器 3 次 + `curl` 4 次）全部返回完整回答、助手消息 `COMPLETED`，但扣费流水均为 `REFUNDED`，`chat_count` 未增加；每次同时出现两条日志：

```
14:43:48.212 [rag-async-1] INFO  RagChatService - 本次对话未下发有效内容，按无产出不计费处理: chargeId=a8e026ac-..., result=REFUNDED
14:43:49.130 [ForkJoinPool.commonPool-worker-1] ERROR QuotaService - [ALERT] 已下发产出但扣费流水未能置为已结算，可能被补偿作业误退: chargeId=a8e026ac-...
```

- 最小复现：admin 登录 → 调试对话（窗口 1）发送任意问题 → 查询
  `select status from wgh_quota_charge where session_id=<id> order by id desc limit 1`，得到 `REFUNDED`，而对应助手消息为 `COMPLETED`。
- 判定依据：退款日志线程为 `rag-async-*`（编排线程），`markOutput` 的结算告警线程为 `ForkJoinPool.commonPool-*`（模型流式回调），时间上前者早于后者 0.6~0.9s；助手消息落库晚于退款。说明编排在流式产出前返回并执行了“无产出退款”，随后首包才到达，`markChargeSettled` 对已退款流水更新 0 行。
- 结论：产品缺陷（计费链路），不是用例过期。影响：普通对话全部免费、产生持续告警噪声。

### 3.2 BUG-02（中）`GET /api/admin/scheduler/instances` 500

- 关联用例：SCHED-26（失败）、SCHED-27（阻塞）
- 现象：接口返回 `{"code":500,"message":"操作失败"}`；后端异常：

```
BadSqlGrammarException: Error attempting to get column 'now' from result set.
Cause: PSQLException: Cannot convert the column of type TIMESTAMPTZ to requested type java.time.LocalDateTime.
```

- 定位：`SchedulerInstanceMapper#now()` 的 `SELECT now()` 映射到 `LocalDateTime`，PostgreSQL 返回 `timestamptz`。
- 同类接口 `/api/admin/scheduler/reconcile`、`/tasks/running?type=CHAT`、`/quota/refunds` 均正常。

### 3.3 BUG-03（中）失联实例作业提前回收后未刷新 `scheduled_at`，重试变“排队超时失败”

- 关联用例：SCHED-28（失败）
- 复现：插入 `status=RUNNING`、`lease_owner=e2e1124-dead`、`lease_expire_time=now()+10min` 的 `WF_RUN` 作业，并放置一个心跳过期的实例；8s 内作业被回收（`lease_owner` 清空），但状态最终为 `FAILED / JOB_QUEUE_TIMEOUT / 排队超过上限，未被执行`，未按 `LEASE_LOST` 重试。
- 原因（静态核对）：`ExecutionJobMapper#reclaimByOwner` 只改状态与 `error_code`，不重置 `scheduled_at`；随后 `expireQueued` 以 `scheduled_at < now() - queueTimeout` 判定排队超时，导致刚回收的作业立即被判失败，`INSTANCE_LOST`（"重试、再失联"）路径实际不可达。
- 影响：失联实例持有的作业无法重试，业务只能靠人工重放。

## 6. 其他观察（不计为失败）

1. **客户端断连噪声**：`curl` 中断或浏览器刷新时，Tomcat 异步链路打印 `Broken pipe` 堆栈（10+ 次），发生在 `SseExecutionStreamSink.emit` 写失败时；功能上生成继续、消息完整，但日志级别为 ERROR，建议收敛为 DEBUG/WARN。

4. **前端并行改动**：工作区存在另一条线对配额退款操作按钮的修改，本次页面巡检未出现构建失败或白屏，结论按当前工作区代码成立。

### 9.3 缺陷（本轮新增/状态更新）

**BUG-04（中，已修复并复测通过）计数读失败返回通用 500，而非约定的 5004**

**BUG-05（中，已修复并复测通过）fail-open 在事务内失效**

- 关联：QCHG-31。

**BUG-06（低，已修复并复测通过）分享链接过期判断存在 8 小时时差**

- 关联：SSE-10 环境构造。
- 现象（修复前）：`wgh_share_link.expires_at` 为 zone-less `timestamp`，与 Java 本地时间比较出现 8 小时偏差，`now()+2h` 的链接被判「已过期」。

**BUG-07（低，已修复并复测通过）重放总开关关闭时未上报 `fallbacks{reason=disabled}`**

- 关联：SSE-12。
- 修复前：`enabled=false` 时断连与重连语义正确，但无 `fallbacks{reason=disabled}` 指标。

**QCHG-27（已修复并复测通过）双 HITL 复用未决流水**
